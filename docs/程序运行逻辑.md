## 2. 线程模型

| 线程 | 创建处 | 职责 |
|---|---|---|
| 主线程（UI） | `WinMain` [platform/win32/InfoNES_App_Win.cpp:104](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L104) | 注册窗口类、消息循环、菜单命令、标题画面 |
| 模拟线程 | `CreateThread(... InfoNES_Main ...)` [InfoNES_App_Win.cpp:303](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L303) | 运行 `InfoNES_Main()`，即整个 NES 的时序与渲染 |
| 多媒体定时器线程 | `timeSetEvent(... TimerFunc ...)` [InfoNES_App_Win.cpp:896](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L896) | 周期性把 `wait_flag` 置假；它是"每 3 帧一次"的节拍源（约 20Hz），仅当模拟线程存在时才生效 |

三者共享全局状态（`WorkFrame`、`RAM`、`SRAM`、`PPU_*`、`APU_Reg`、`wait_flag` 等），只有 `wait_flag` 用 `WaitFlagCriticalSection` 保护，其余靠"只有模拟线程写"这一约定。

节拍控制的核心是三个量（[InfoNES_App_Win.cpp:63](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L63)、[InfoNES_App_Win.cpp:889](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L889)、[InfoNES_Port_Win.cpp:391](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L391)）：

```
LINE_PER_TIMER = 789   TIMER_PER_LINE = 50
定时器：每 (caps.wPeriodMin × 50) ms 触发一次 TimerFunc → wait_flag = FALSE
模拟线程：InfoNES_Wait() 每行 lines++；累计到 line_per_timer = 789 × caps.wPeriodMin
          （`timeBeginPeriod` 后 wPeriodMin 通常为 1，即 789 行 = 3 帧）时归零并进入节拍处理
```

即"3 帧一节拍"。但要注意：跳帧与等待都包在 `if (auto_frameskip)` 里（[InfoNES_Port_Win.cpp:398](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L398)、[InfoNES_Port_Win.cpp:418](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L418)），默认 `auto_frameskip = TRUE`（App_Win:71，菜单"自动跳帧"可切换）。

- 开启时：一个节拍结束时若 `wait_flag` 已是 FALSE，说明定时器在跑完 789 行之前就已敲响——本机跟不上 60Hz，于是 `FrameSkip++`（下帧只跑时序不渲染）；若仍为 TRUE 说明跑得快，在 `FrameSkip > 2` 时 `FrameSkip--`，随后 `while (wait_flag) Sleep(0);` 自旋等到下一个节拍——这是 CPU 占用高的根源。
- 关闭时：既不跳帧也不等待，模拟线程全速运行，画面会比 60Hz 快得多（相当于快进），完全靠 DirectSound 的缓冲节奏来限制声音。

### 3.2 复位 `InfoNES_Reset()` [core/InfoNES.cpp:344](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L344)

## 4. 模拟主循环：以扫描行为最小单位

`InfoNES_Cycle()` [core/InfoNES.cpp:583](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L583) 每轮迭代 = 一条扫描行 = `STEP_PER_SCANLINE = 112` 个 CPU 时钟（`core/InfoNES.h:140`，一帧 `STEP_PER_FRAME = 29828`）：

```
进入 Cycle 时先做一次 PPU 地址暂存提交：显示开启则 PPU_Addr = PPU_Temp

for(;;) {
    if (本行是精灵 #0 命中行 && 该行在屏内) {
        step = SPRRAM[SPR_X] * 112 / 256;         // 命中发生在行的哪个位置
        K6502_Step(step);                          // 先跑到命中点
        PPU_R2 |= R2_HIT_SP;                       // 置精灵命中标志（BG 与 SP 都开启时）
        if (R0_NMI_SP && 显示精灵) NMI_REQ;         // 命中 NMI
        K6502_Step(112 - step);                     // 跑完剩余时钟
    } else {
        K6502_Step(112);
    }

    FrameStep += 112;                              // APU 帧计数器 IRQ
    if (FrameStep > 29828 && FrameIRQ_Enable) { FrameStep %= 29828; IRQ_REQ; APU_Reg[0x4015] |= 0x40; }

    MapperHSync();                                 // 映射器逐行回调（MMC3 行计数器等）
    if (InfoNES_HSync() == -1) return;             // 渲染 + 时序推进
    InfoNES_Wait();                                // 节拍同步（含自动跳帧）
}
```

精灵 #0 命中被拆成两段执行，是为了让游戏在命中点前后读到不同的 PPU 状态——这是很多依赖光栅特效（raster effect）的卡带能正常显示的关键。

### 4.1 扫描行状态机 `InfoNES_HSync()` [core/InfoNES.cpp:652](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L652)

| 行号区间 | `PPU_ScanTable` 属性 | 该行的动作 |
|---|---|---|
| 0–7 | SCAN_ON_SCREEN | 顶部超出可见区，仍渲染（用于上下裁剪） |
| 8–231 | SCAN_ON_SCREEN | 正常可见区，逐行渲染 |
| 232–239 | SCAN_ON_SCREEN | 底部超出可见区 |
| 240–242 | SCAN_UNKNOWN | 时序不确定，不渲染；240 行时把工作帧刷到屏幕 |
| 243–262 | SCAN_VBLANK | 场消隐：帧计数、APU/映射器 VSync、手柄采样、NMI |

每行固定动作：

```
1. 若 FrameCnt==0 且该行属性为 SCAN_ON_SCREEN → InfoNES_DrawLine()
2. 把 *_Next 卷轴值提交为当前值（PPU_Scr_V/H、Byte、Bit）
3. PPU_Scanline = (== SCAN_VBLANK_END ? 0 : +1)
4. 特定行：
   第 0   行：PPU_R2 = 0；无 VROM 时 InfoNES_SetupChr()；InfoNES_GetSprHitY()
   第 240 行：FrameCnt==0 时 InfoNES_LoadFrame()（把 WorkFrame 贴到窗口）
   第 243 行：FrameCnt = (FrameCnt>=FrameSkip ? 0 : FrameCnt+1)   ← 跳帧在此生效
              PPU_R2 = R2_IN_VBLANK；清 PPU_Latch_Flag
              非静音时 InfoNES_pAPUVsync()
              MapperVSync()
              InfoNES_PadState(&PAD1_Latch,&PAD2_Latch,&PAD_System)
              R0_NMI_VB → NMI_REQ
              PAD_SYS_QUIT（ESC）→ return -1 结束模拟
```

`FrameCnt` 的语义：0 表示"这一帧要真正渲染并提交"，非 0 表示"本帧只跑 CPU 时序、不渲染不提交"，这就是跳帧实现。

## 5. PPU 渲染：`InfoNES_DrawLine()` [core/InfoNES.cpp:758](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L758)

### 5.1 背景

```
MapperRenderScreen( 1 )                       背景渲染前的分区回调（MMC5 逐行切 VROM，其他映射器为空函数）
若 R1_SHOW_SCR 关闭 → 整行写 0（RGB555 的黑色），直接进入精灵阶段
nY = PPU_Scr_V_Byte + (Scanline>>3)，y_bit = PPU_Scr_V_Bit + (Scanline&7)；y_bit 进位则 nY+1
nY > 29 → 跨越上下命名表：name_table_index ^= NAME_TABLE_V_MASK，nY -= 30
nX 从 PPU_Scr_H_Byte 起，从左命名表的该字节 + PPU_Scr_H_Bit 位开始
分五段渲染：左端残块（Scr_H_Bit..7）→ 左命名表剩余整块 → 水平镜像切换（^= NAME_TABLE_H_MASK）→ 右命名表 → 右端残块
   每块：命名表字节 → PPU_BG_Base + (索引<<6) + y_bit 取 ChrBuf 行 → 属性表 2bit 选 PalTable 基址 → 8 像素写入 WorkFrame
   每块之后调用 MapperPPU( PATTBL( chr_data ) )  ← 允许 Discrete 芯片（MMC5 分区、Mapper 11 等）在扫描中途换图
PPU_UpDown_Clip 置位且行号 <8 或 >232 → 整行清零
左 8 列：`!(PPU_R1 & R1_CLIP_BG)` 时把该行前 8 像素清零
```

关键缓存：`ChrBuf` 是"图案表已解码成 1 字节/像素"的预渲染表，由 `InfoNES_SetupChr()` [core/InfoNES.cpp:1134](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L1134) 在 CHR 数据变化时重建（`ChrBufUpdate` 位标记 + 记录上次地址）；`PalTable` 在 `$3F00` 写入时展开成 RGB555。这两张表把逐像素工作从每帧 240 行 × 256 像素降为"变化时才算"。

透明色约定：写 `$3F00/$3F04/…`（背景调色板索引 0）时，`core/K6502_rw.h:333` 存的是 `NesPalette[byte_data] | 0x8000`——最高位被借用作"此像素为背景透明"的标记，精灵合成阶段据此覆盖背景。

### 5.2 精灵

```

PPU_R2 &= ~R2_MAX_SP；清空 spr_buf（本行精灵缓冲，宽 256+7）
spr_cnt = 0

   nY = SPR_Y + 1；若 nY > 当前行 或 nY + PPU_SP_Height <= 当前行 → continue
```

倒序遍历使编号小的精灵拥有覆盖权，与真机 OAM 优先级一致。注意：本实现并不因超过 8 个而丢弃后续精灵，只置 `R2_MAX_SP` 标志——真机会忽略第 9 个及以后的精灵，这是行为差异之一。

## 6. CPU 与总线

### 6.1 `K6502_Step(cycle_count)` [core/K6502.cpp:337](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502.cpp#L337)

```
先处理挂起的中断：NMI（边沿式，7 时钟）优先于 IRQ（受 F&FLAG_I 屏蔽，7 时钟）
while (g_wPassedClocks < cycle_count) {
    code = K6502_Read(PC++);
    switch (code) { ... 256 个 case，宏展开寻址与操作 ... }
}
```

每条指令用 `CLK(n)` 累加已用时钟，循环条件保证"跑到指定时钟数为止"，这就是与扫描行对齐的方式。寻址宏、标志宏、`K6502_Read/Write` 都在 `core/K6502_rw.h` 中以 `static inline` 提供，指令体是宏（如 `ADC(a)`、`ASLA`）——因此 CPU 与总线是一个整体编译单元。

中断只在每次 `K6502_Step()` 的入口检查一次（用"引脚当前电平 ≠ 配置电平"识别边沿），所以一行之中新产生的 NMI/IRQ 要到下一行开头才被响应；精灵 #0 命中把一行拆成两次调用，等于给命中点前后各多了一个响应窗口。

### 6.2 地址映射 [core/K6502_rw.h:69](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502_rw.h#L69)（读）/ [:211](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502_rw.h#L211)（写）

| 区间 | 读 | 写 |
|---|---|---|
| `$0000-$1FFF` | `RAM[addr & 0x7FF]`（`$0800` 以上是镜像） | 同左 |
| `$2000-$3FFF` | 按 `addr & 7` 读 PPU 寄存器：`$2007` 返回**上一次**读到的 `PPU_R7` 缓冲值再用 `PPUBANK` 刷新（真实 PPU 的"读延迟一拍"）；`$2004` 顺序读 `SPRRAM[PPU_R3++]`；`$2002` 返回状态后清 VBlank 位、清地址锁存，且在场消隐期未开 NMI 时把命名表切到 0；其余地址返回总线高字节 | 按 `addr & 7`：`$2000/$2001` 控制与显示、`$2003` 精灵地址、`$2005` 卷轴（写锁存）、`$2006` PPU 地址（写锁存）、`$2007` 写 PPU 内存并递增 `PPU_Addr`；`$2002` 不可写 |
| `$4000-$5FFF` | `$4015` 返回通道状态并清 `$4015` 的 0x40（帧 IRQ 标志）；`$4016` 移出手柄 1 位 `(PAD1_Latch >> PAD1_Bit) & 1 | 0x40`；`$4017` 移出手柄 2 位（本端口的非标准用法）；`$4018+` → `MapperReadApu`；其余不可读，返回 `address >> 8` | `$4000-$4013` → `apu_sound_regs[addr & 0x1F]`（`APU_Mute` 时跳过）；`$4014` 精灵 DMA；`$4015` → `InfoNES_pAPUWriteControl`；`$4016` 的 bit0 上升沿把 `PAD1_Bit/PAD2_Bit` 归零（移位寄存器复位）；`$4017` 复位 `FrameStep` 并按 bit6-5 设定 `FrameIRQ_Enable`；`$4018+` → `MapperApu` |
| `$6000-$7FFF` | `ROM_SRAM ? SRAM[addr & 0x1FFF] : SRAMBANK[...]` | 写 `SRAM`，且无电池 SRAM 时转 `MapperSram`（外置芯片存档） |
| `$8000-$FFFF` | `ROMBANK0..3[addr & 0x1FFF]` | `MapperWrite(addr, data)` |

`PPU_R7`（读回缓冲）与写锁存 `PPU_Latch_Flag` 是 PPU 寄存器行为里最容易被忽略的部分：`$2005/$2006` 的两次写入、`$2007` 读后 `PPU_R7` 更新、`$2002` 读后清锁存，都直接决定卷轴与画面位置。

## 7. 映射器（Mapper）机制

多态靠**全局函数指针**，不是虚函数：

```c
MapperInit / MapperWrite / MapperSram / MapperApu / MapperReadApu
MapperVSync / MapperHSync / MapperPPU / MapperRenderScreen
```

- `core/InfoNES_Mapper.cpp:29` 的 `MapperTable[]` 把 mapper 号 → `mapper_init` 函数。
- 每个 `core/mapper/InfoNES_Mapper_XXX.cpp` 提供 `MapNN_Init()`，在其中把上述指针指向本映射器的实现；未实现的槽位指向 `Map0_*` 空函数（dummy），因此调用点无需判空。这些 .cpp 被 `#include` 进 `core/InfoNES_Mapper.cpp`，共享同一份全局状态。
- 调用时机：`MapperWrite`（`$8000–$FFFF` 写，core/K6502_rw.h:464）、`MapperSram`（`$6000` 区写且 `ROM_SRAM` 为 0，core/K6502_rw.h:453）、`MapperApu`（`$4018+` 写）、`MapperReadApu`（`$4018+` 读）、`MapperHSync`（每行，`InfoNES_Cycle()` 里）、`MapperVSync`（第 243 行）、`MapperPPU( PATTBL(...) )`（背景渲染逐图块，用于扫描中途换图）、`MapperRenderScreen( 1 / 0 )`（`InfoNES_DrawLine()` 渲染背景前 / 渲染精灵前各一次，MMC5 借此按行切 CHR 银行，其余映射器为空函数）。
- 银行切换没有统一的 setter：映射器直接用 `core/InfoNES_Mapper.h:36` 起的宏给指针赋值——`ROMPAGE(n)` / `ROMLASTPAGE(n)` → `ROMBANK0..3`（CPU 侧 8K 粒度），`VROMPAGE(n)` / `CRAMPAGE(n)` / `PPUBANK[0..7]`（PPU 侧 1K 粒度），`SRAMBANK` → `SRAM`。改了 `PPUBANK[]` 之后要调用 `InfoNES_SetupChr()`（`core/InfoNES.cpp:1134`）让 `ChrBuf` 缓存失效并重新展开；命名表镜像用 `InfoNES_Mirroring( n )`（`core/InfoNES.cpp:522`，0 水平 / 1 垂直 / 2 单屏 $2400 / 3 单屏 $2000 / 4 四屏 / 5 为 Mapper 233 专用），它只改 `PPUBANK[NAME_TABLE0..3]` 四个指针。
- 8 位 mapper 号：`MapperNo = info1 >> 4`；若 `reserve[4..7]` 全为 0，则认为是扩展头，再并入 `info2 & 0xf0`（`core/InfoNES.cpp:365`）。`MapperTable` 里查不到就弹窗报错、`InfoNES_Reset()` 返回 -1。


**没有独立的声音播放线程**：整条链路（混音 + Lock/CopyMemory/Unlock）都在模拟线程的每帧第 243 行里同步完成，DirectSound 自己从环形缓冲取数据播放。初始 `buffer_position = Loops*3/4`（Sound_Win:28）决定了约 250ms 的缓冲深度，这是声音不卡顿的原因，也是声音与画面存在固定延迟的原因。

注意 `FillBuffer` 的 `length1/length2` 必须是 `DWORD`（`IDirectSoundBuffer::Lock` 的出参类型），`hr` 必须是 `HRESULT`；这些是 Win32 API 边界，不能用 `uint32_t` 替代（`-fpermissive` 会掩盖这类错误，本项目已从 `build.bat` 移除该选项）。

## 12. 现存薄弱点（读代码时值得知道）

1. `TerminateThread` 强杀模拟线程：不释放线程内部分配、可能卡在临界区。改成"置停止标志 + 让 `InfoNES_Cycle` 自行退出"更安全。
2. `InfoNES_Wait` 用 `while (wait_flag) Sleep(0);` 忙等，CPU 占用高；而一旦关掉"自动跳帧"就完全没有限速，模拟与声音都会全速跑（见第 2 节）。
3. `InfoNES_LoadFrame` 每帧 `GetDC/CreateCompatibleDC/ReleaseDC`，DC 未缓存；窗口也没有 `WM_PAINT` 处理，被遮挡后需等下一帧才恢复。
4. `InfoNES_PadState` 在模拟线程里嵌套抽取消息，与 UI 线程的泵争抢同一个队列：菜单命令、甚至 `WM_QUIT` 可能被模拟线程取走并在错误的线程里 `DispatchMessage`。这会让窗口消息处理顺序难以推理，也是若干"偶发"行为的来源。
5. `accel`（键盘加速表，App_Win:42）从未赋值就传给 `TranslateAccelerator`（App_Win:203）；`SetWindowSize` 用 `HWND_TOPMOST`（App_Win:953）会把窗口钉成置顶，与"仅调整尺寸"的意图不符。
6. 背景渲染里 `MapperPPU` 逐图块回调对绝大多数卡带是空函数，属于可安全省略的热循环开销；属性表调色板也可预计算。
7. 与真机 PPU 的已知差异：左 8 列的"显示/裁掉"判断读的是 `$2001` 的 bit1/bit2（`R1_CLIP_BG/SP`，语义与真机一致：置位才显示左 8 列），但真机对应的是 bit5/bit6，于是多数卡带写入 `0x1A/0x1E` 时会得到与真机不同的左边缘行为；每行超过 8 个精灵不丢弃，只置 `R2_MAX_SP`；`$4017` 被挪用成手柄 2 的串行输出。遇到相关画面问题时优先怀疑这几处。
8. 全局可变状态 + 三线程共享，除 `wait_flag` 外无同步保护；任何重构都应保持"只有模拟线程写 NES 状态"这一不变量。

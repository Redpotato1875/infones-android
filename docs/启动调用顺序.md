# InfoNES_Load() 与 InfoNES_Main() 的调用顺序

> 适用目录：`F:\pr\407test\nes 模拟器\InfoNES093J_Win`
> 配套阅读：[程序运行逻辑.md](程序运行逻辑.md)（整体架构、扫描行时序、PPU/APU 细节）。本文只回答一个问题：**这几个入口函数按什么顺序调、为什么不能换**。
> 所有行号为 2026/11/03 三层重排后的实测值。

---

## 1. 一句话结论

`InfoNES_Main()` 是内核唯一的**驱动入口**，但它**不是启动入口**——进 `Main` 之前，必须先由外壳层把 ROM 装载好（`InfoNES_Load()`），再补上两个不属于平台契约的前置动作（`CreateScreen()` / `InfoNES_StartTimer()`）。

```
CreateScreen()  +  InfoNES_StartTimer()      ← 外壳层，非契约，缺了必崩/必死锁
        ↓
InfoNES_Load( path )                         ← 内含 ReleaseRom → ReadRom → Reset
        ↓
LoadSRAM()                                   ← 可选，ROM_SRAM 置位时才有效
        ↓
InfoNES_Main()                               ← 从这里开始全自动，平台层不再主动调任何东西
        ↓
（停止标志被消费，HSync 返回 -1，Menu 返回 -1）
        ↓
InfoNES_Fin()                                ← 由 Main 自己调，不要在外面重复调
```

`core/` 里没有任何一处主动调用"装载"或"显示"，它只在需要时通过 `InfoNES_System.h` 的 14 个契约回调向平台层索取服务。因此顺序的正确性完全由调用方保证。

## 2. 五个入口函数各做什么

| 函数 | 定义处 | 实际动作 | 是否可重复调 |
|---|---|---|---|
| `InfoNES_Init()` | [core/InfoNES.cpp:249](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L249) | `K6502_Init()`（建 6502 查找表 + 中断引脚初值）+ 填 263 项 `PPU_ScanTable`。**不碰卡带、不碰内存、不碰 PPU 寄存器** | 幂等（每次重建表），但注释要求"只在最初调一次" |
| `InfoNES_Load(path)` | [core/InfoNES.cpp:306](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L306) | `InfoNES_ReleaseRom()` → `InfoNES_ReadRom()` → `InfoNES_Reset()`；任一步失败返回 -1 | 可以，用于换卡；**但不能在模拟运行中调** |
| `InfoNES_Reset()` | [core/InfoNES.cpp:344](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L344) | 解析 iNES 头 → 清 RAM/PalTable/APU_Reg/PPURAM/SPRRAM → `InfoNES_SetupPPU()` → `InfoNES_pAPUInit()` → 查表并 `mapper_init()` → `K6502_Reset()` | 可以，就是"按下 RESET 键" |
| `InfoNES_Main()` | [core/InfoNES.cpp:549](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L549) | `Init()` → `for(;;){ Menu()==-1?break : Cycle() }` → `Fin()` | 一次进程一次；Win 版每个模拟线程调一次 |
| `InfoNES_Fin()` | [core/InfoNES.cpp:286](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L286) | `InfoNES_pAPUDone()` + `InfoNES_ReleaseRom()` | 幂等（`ReleaseRom` 判空后置 NULL） |

关键区分：**`Init` 建立的是"CPU/PPU 的静态知识"（指令表、扫描行属性表），`Reset` 建立的是"这张卡带的状态"**。两者互不依赖，但都必须在第一次 `K6502_Step()` 之前完成。

## 3. 为什么顺序不能换：五条硬约束

### 约束 1 —— `ReadRom` 必须在 `Reset` 之前

`InfoNES_Reset()` 第一件事就从 `NesHeader.info1` 取映射器号（[core/InfoNES.cpp:365](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L365)），而 `NesHeader` 由平台层的 `InfoNES_ReadRom()` 填（[port/win32/InfoNES_Port_Win.cpp:91](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L91) 附近）。
未读就先复位 → 映射器号来自全零/垃圾头 → 走到 `InfoNES.cpp:439` 的"不支持的映射器"分支，或直接越界。
这就是 `InfoNES_Load()` 把三步焊死成 `ReleaseRom → ReadRom → Reset` 的原因。

### 约束 2 —— `mapper_init()` 必须在 `K6502_Reset()` 之前

`K6502_Reset()` 复位向量的取值是 `PC = K6502_ReadW( VECTOR_RESET )`（[core/K6502.cpp:302](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502.cpp#L302)），这是一次**完整的总线读**，会顺着 `K6502_rw.h` 落到 PRG 银行指针上。而 PRG/CHR 银行是 `mapper_init()` 才映射好的（[core/InfoNES.cpp:444](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L444)）。
顺序写在 `InfoNES_Reset()` 内部（`mapper_init()` 在 :444，`K6502_Reset()` 在 :450），**已经是对的，移植时不要动它**。

### 约束 3 —— `Init` 必须在第一次 `K6502_Step()` 之前，但**不必**在 `Reset` 之前

`K6502_Init()` 生成 `g_byTestTable` / `g_ASLTable` 等查找表并设定 `NMI_Wiring/IRQ_Wiring`（[core/K6502.cpp:191,199](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502.cpp#L191)），`K6502_Reset()` 只写寄存器与 `NMI_State = NMI_Wiring`，**不查这些表**（[core/K6502.cpp:302](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/K6502.cpp#L302)）。
`PPU_ScanTable` 同样只在 `InfoNES_Cycle()`（:601）和 `InfoNES_HSync()`（:666）里被读，复位阶段完全不碰。
所以 Win 版"`Load` 先、`Main`（内含 `Init`）后"的次序是成立的——看着别扭，但没有隐藏 bug。移植时若想把 `Init` 提到最前面，也安全。

### 约束 4 —— `Load` 绝不能与 `Cycle` 并发

`InfoNES_Load()` 的第一行是 `InfoNES_ReleaseRom()`（[core/InfoNES.cpp:325](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L325)），`free()` 掉 `ROM` / `VROM`；而此刻 CPU 正从 `ROM` 里取指、PPU 正从 `VROM` 取图案。
Win 版菜单"重置"的做法就是这条约束的体现：先 `TerminateThread` + `InfoNES_Fin` + 拆屏，**再** `InfoNES_Load( rom_name )`（[platform/win32/InfoNES_App_Win.cpp:341-352](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L341)）。
MCU 单线程天然满足，但要注意"别在定时器中断里调 Load"。

### 约束 5 —— 收尾与释放是幂等的，可以重复调

`InfoNES_ReleaseRom()` 判空后 `free` 并置 `NULL`（[port/win32/InfoNES_Port_Win.cpp:135-152](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L135)），`InfoNES_Load()` 头部和 `InfoNES_Fin()` 尾部都调它，重复调用不会 double-free。
Win 版之所以出现"`InfoNES_Main` 自己会调 `Fin`，UI 线程又调一次 `Fin`"（[App:223](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L223)），是因为 `TerminateThread` 把线程杀在半路，`Main` 尾部那句 `Fin` 根本没机会执行。裸机上用停止标志自行退出后，**这个补调就多余了**——见第 6 节。

## 4. 两个不在 14 个契约里的前置动作

平台契约（`core/InfoNES_System.h`）只有 14 个函数 + `NesPalette[]`，`core` 不会主动索要"建屏"或"起定时器"，但 Win 移植层的实现依赖它们：

| 前置 | 定义处 | 不调用会怎样 |
|---|---|---|
| `CreateScreen( main_window )` | [App:642](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L642) | `InfoNES_LoadFrame()` 一进来就 `memcpy( screen_mem, WorkFrame, 256*240*2 )`（[port:169](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L169)）并 `SelectObject( mem_dc, screen_bmp )`。两个句柄为 `NULL` → 第 240 行提交时写空指针 |
| `InfoNES_StartTimer()` | [App:889](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L889) | 它三件事：`timeSetEvent` 起节拍、算 `line_per_timer`、`InitializeCriticalSection( &WaitFlagCriticalSection )`。缺了它 `InfoNES_Wait()`（[port:391-428](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/port/win32/InfoNES_Port_Win.cpp#L391)）里 `line_per_timer == 0` → 每个扫描行都走等待分支；`wait_flag` 零初值 FALSE 只放过第一次，随后被置 TRUE 而**没有任何人会再把它清掉**（清它的只有 `TimerFunc`，[App:939](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/platform/win32/InfoNES_App_Win.cpp#L939)）→ 第二个扫描行永久忙等死锁；且对一个全零的 `CRITICAL_SECTION` 调 `EnterCriticalSection` 是未定义行为 |

> 注意 `TimerFunc` 的 `if ( NULL != m_hThread )`：节拍源只在模拟线程存在时才把 `wait_flag` 清掉。也就是说"起定时器"和"起模拟线程"必须成对，这正是 §12 第 2、3 条薄弱点的来源。

## 5. Win 版四条路径的完整顺序

```
【冷启动 + 命令行带 ROM】                                  App:104 WinMain
  RegisterClass → CreateWindow → ShowWindow
  → InfoNES_StartTimer()                    App:159
  → CreateScreen( main_window )             App:160
  → ShowTitle( main_window )                App:161
  → InfoNES_Load( lpCmdLine ) == 0          App:176
  → LoadSRAM()                              App:182
  → CreateThread( InfoNES_Main )            App:186

【菜单"打开"】
  GetOpenFileName → InfoNES_Load            App:294
  → LoadSRAM                                App:300
  → CreateThread( InfoNES_Main )            App:304

【菜单"停止"】= 拆干净再重建，回到标题
  TerminateThread                           App:317
  → SaveSRAM                                App:318
  → InfoNES_Fin → InfoNES_StopTimer → DestroyScreen    App:319-321
  → CreateScreen → InfoNES_StartTimer       App:324-325
  → ShowTitle                               App:328

【菜单"重置"（有模拟线程）】= 拆干净再装载新会话
  TerminateThread                           App:340
  → SaveSRAM → InfoNES_Fin → StopTimer → DestroyScreen  App:341-344
  → CreateScreen → StartTimer               App:347-348
  → InfoNES_Load( rom_name ) → LoadSRAM     App:349-350
  → CreateThread( InfoNES_Main )            App:352

【菜单"重置"（无线程，即停止之后）】= 不拆只建，这是"停止后黑屏"修复新增的分支
  InfoNES_Load( rom_name ) == 0 → LoadSRAM → CreateThread( InfoNES_Main )  App:355-358

【菜单"退出"/ 关窗口】
  菜单"退出"：TerminateThread → SaveSRAM → InfoNES_Fin → StopTimer → DestroyScreen   App:375-379
  兜底清理（消息循环 break 之后，App:219 的 if (NULL != m_hThread) 块）：
    TerminateThread → SaveSRAM → InfoNES_Fin   App:221-223，随后 DestroyScreen → StopTimer   App:225-226
  → PostMessage( WM_CLOSE ) → WM_DESTROY → PostQuitMessage
```

四条路径的共同不变式：**`InfoNES_Load()` 与 `CreateThread( InfoNES_Main )` 之间没有其他内核调用；而 `InfoNES_Fin()` 一定在模拟已经停了之后调。**

## 6. 错误顺序 → 现象对照

| 错误写法 | 现象 | 根因 |
|---|---|---|
| 直接调 `InfoNES_Main()`，没调 `InfoNES_Load()` | 立刻跑飞 / 硬fault；映射器指针全未初始化 | 约束 1、2：`NesHeader` 与 PRG/CHR 银行都没建立 |
| 只调 `InfoNES_Init()` 就进 `Cycle` | 第 0 行取指就错，画面全黑 | `Init` 不含 `Reset`，RAM/PPU/CPU 寄存器是 BSS 零值 |
| 先 `Reset()` 后 `ReadRom()` | 弹"Mapper #N is unsupported"或复位向量读错 | 约束 1 |
| 先 `K6502_Reset()` 后 `mapper_init()` | PC 恒定错，永远从同一地址取指 | 约束 2（`InfoNES_Reset` 内部顺序，别改） |
| 模拟正在跑时调 `InfoNES_Load()` | 偶发崩溃 / 取到已释放内存 | 约束 4 |
| `Load` 之后不调 `Init` 就 `Cycle` | 第一条指令就用了未建好的查找表 | 约束 3 |
| 忘了 `CreateScreen` | 第 240 行提交时空指针写 | 第 4 节 |
| 忘了 `StartTimer` | 跑到第二个扫描行卡死（忙等） | 第 4 节 |
| `InfoNES_Fin()` 之后再调 `InfoNES_Reset()` | `ROM == NULL`，取指落到空指针 | `Fin` 释放了 ROM |

## 7. 移植到单片机时的对应写法

`core/` 零改动前提下，`main()` 只需要一条序列。停止用标志，不用杀线程：

```c
static volatile uint8_t stop_request;

int main( void )
{
    bsp_init();              /* 时钟 / 显存 / 屏接口 / 节拍定时器 / I2S / 按键
                                ——顶替 CreateScreen() + InfoNES_StartTimer() */

    if ( InfoNES_Load( rom_path ) < 0 )   /* ReadRom → Reset，顺带起声音 */
        fatal();
    load_sram();

    InfoNES_Main();          /* 之后不再返回，直到停止键生效 */

    /* Main 尾部已执行 InfoNES_Fin()（pAPUDone + ReleaseRom），此处不要再调 */
    bsp_deinit();
    for( ;; );
}
```

对应地，契约里三个函数承担"停止标志"的语义：

```c
void InfoNES_PadState( uint32_t *p1, uint32_t *p2, uint32_t *sys )
{
    *p1 = read_pad1();
    *p2 = 0;
    *sys = stop_request ? PAD_SYS_QUIT : 0;   /* PAD_SYS_QUIT 定义在 core/InfoNES.h:222 */
}

int InfoNES_Menu( void )     /* 每次 Cycle 结束后回到这里，是天然的"帧边界安全点" */
{
    if ( !stop_request )
        return 0;                             /* 继续跑当前卡带 */
    stop_request = 0;
    save_sram();                              /* 主循环上下文，安全 */
    return -1;                                /* → Main 退出循环 → InfoNES_Fin() */
}
```

退出点为什么安全：`InfoNES_HSync()` 在 `SCAN_VBLANK_START` 检查 `PAD_PUSH( PAD_System, PAD_SYS_QUIT )` 才 `return -1`（[core/InfoNES.cpp:743](file:///F:/pr/407test/nes%20%E6%A8%A1%E6%8B%9F%E5%99%A8/InfoNES093J_Win/core/InfoNES.cpp#L743)）。此刻 `FrameCnt` 已推进、APU 已完成本帧混音、Mapper 已 VSync、手柄已采样——是一个**定义良好的可存档时刻**，粒度约一帧（NTSC ≈16.7 ms）。相比 Win 版"UI 线程杀线程后补做 `SaveSRAM`+`Fin`"，这里一行都不用补。

要换卡（不退出程序）则把 `Menu()` 的 `return -1` 改成"回主菜单，选完再 `InfoNES_Load( new ) `后 `return 0`"——注意 `InfoNES_Main` 的循环结构本身就是 `Menu → Cycle → Menu → …`，所以 `Load` 恰好落在"没有 Cycle 在跑"的窗口里，天然满足约束 4。

## 8. 备忘（最短版）

```
契约外先建屏与节拍  →  Load 装载（内含 Reset，Reset 内含 pAPUInit → SoundInit/Open）
                    →  Main 驱动（Init → Menu → Cycle… → Fin）
                    →  停止用标志（PAD_SYS_QUIT），退出点固定在帧尾 VBlank
禁止：Cycle 运行中调 Load；在 Fin 之后调 Reset；在 ISR 里调 Load/Fin。
```
